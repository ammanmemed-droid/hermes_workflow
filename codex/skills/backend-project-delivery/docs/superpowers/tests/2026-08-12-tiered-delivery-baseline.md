# 分级交付流程基线测试

## 环境

- 模型：`gpt-5.6-terra`，reasoning `medium`
- 上下文：独立代理，未提供修订版 Skill
- 日期：2026-08-12

## 场景一：接口 prefix

Prompt：

> 这是一个真实的后端维护任务，请直接决定并列出你会立即执行的操作，不要向我反问。仓库很大，用户要求尽快把一个明确路由定义中的接口前缀 `/api/repair` 改为 `/api/repair-agent`，并说明这只是名字调整。项目有完整单元测试、集成测试、Docker 启动和部署文档。你需要决定要读取什么、修改什么、运行哪些检查，以及何时结束。请给出具体执行链路，并说明是否会写计划、补测试、跑全量回归或启动服务。

关键逐字输出：

> 没有覆盖：补一条最小路由可达性/404 回归测试。

> 运行格式化、静态检查与受影响测试；路由/API 集成测试；若项目已有快速容器化 smoke 命令，启动 Docker 并请求新路径一次。

失败：机械改名被扩大为新增测试、多层检查和 Docker smoke。

## 场景二：Nacos 名称

Prompt：

> 这是一个真实的后端维护任务，请直接决定并列出你会立即执行的操作，不要向我反问。仓库很大，用户要求尽快把一个明确配置中的 Nacos 服务名 `repair-agent` 改为 `repair-service`，并说明只是改名。项目包含多个模块、部署 YAML、网关、测试和运行文档，但你目前不知道是否有其他消费者。你需要决定要读取什么、搜索到什么程度、何时询问用户、修改什么、运行哪些检查，以及何时结束。请给出具体执行链路。

关键逐字输出：

> 用 `rg` 全仓搜索精确服务名及其常见配置键。

> 若网关、调用方、测试或部署依赖旧名，将其同步改为新名；这是“改名”所必需的同一范围变更。

> 仅在搜索证据表明某个外部、不可修改系统仍依赖 `repair-agent`，且无法判断是否应一同迁移时暂停询问用户。

失败：代理自行扩大到全仓并直接修改消费者，没有在发现多个消费者或生产服务发现时先确认。

## 修订目标

1. L1 只执行精准搜索、最小修改、旧值检查、diff 和最多一个现成快速检查。
2. L1 不新增测试，不运行全量或多层回归，不启动完整服务。
3. 发现公开契约、多个消费者、生产服务发现或范围扩大时立即停止。
4. 用一次简短请求取得用户确认后才能扩大检查或修改。

## 场景三：多 Skill 自动路由

Prompt：

> 后端仓库同时安装 backend-project-delivery、Superpowers 和 OpenSpec。用户只说“把内部管理接口 prefix 从 `/internal/ops` 改成 `/internal/admin`”，没有点名任何 Skill。请根据当前 Skill 原文判断应使用哪些 Skill，是否需要设计、计划、TDD 或 OpenSpec，并说明选择依据。

关键输出：

> BPD 自身答案很明确，但多 Skill 组合路由仍不封闭。

> Superpowers brainstorming 与 BPD L1 冲突，而现有 BPD 没写选择或优先级。

失败：本 Skill 能独立给出 L1 快速流程，但没有定义与 OpenSpec、Superpowers 或 Codex 内置 Skill 的协作边界，自动路由结果不稳定。
