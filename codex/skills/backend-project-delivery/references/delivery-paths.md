# 项目开发路径

仅在 L2 或 L3 读取。任务等级决定流程深度；本文件只决定采用哪类工程方法。新证据推翻原分类时重新分类。

## 从零开发（Greenfield）

适用于不存在有意义实现的项目。

1. 从权威资料提取核心流程、业务规则、非功能要求、验收标准和非目标。
2. 明确系统边界、数据归属和上下游职责。
3. 实现集成前定义 API、事件、状态、错误、幂等、安全、超时和失败语义。
4. 建立与任务相称的最小工程基线，并先完成一条可运行、可测试的纵向流程。

不要擅自创造缺失的业务字段或外部契约。

## 存量迭代（Brownfield）

适用于已运行平台的增量行为修改。

1. 只读检查目标模块、工作区状态、真实行为、相关测试和直接契约。
2. 优先沿用既有模式并进行最小完整修改。
3. 为需要保持的行为补充必要特征测试，再对新行为使用 TDD。
4. 只验证实际受影响的消费者、数据、权限和失败路径。

不要把增量需求扩大成框架迁移、大范围清理或架构重写。

## 优化（Optimization）

修改前定义可重复基线、主指标和护栏指标，用分析证据定位瓶颈。每次只改变一个因素，用相同条件比较，并只保留有实测收益且未恶化护栏的修改。

## 稳定化（Stabilization）

先复现并保留准确命令、环境和错误证据，再跨配置、逻辑、存储及依赖追踪根因。条件允许时先建立失败测试或确定性复现，然后实施最小根因修复并扩大到必要回归。

不得掩盖必需依赖、吞掉错误或用 Mock 宣称真实流程已恢复。

## 重写（Rewrite）

仅在用户明确授权替换时使用。盘点功能对等、消费者、数据、权限和运维行为；定义共存、迁移、切换、回滚和下线方案，并使用契约、数据、集成、安全和运维证据证明对等。

代码质量差本身不等于获得重写授权。

## 知识边界

- 仓库命令和编码规范放入仓库指令文件。
- 架构、Schema 和业务规则放入获准的项目资料。
- 不保存凭据、内部地址、专有代码、客户数据或事故细节。
