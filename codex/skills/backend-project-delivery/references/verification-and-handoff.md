# 验证与交付

仅在 L2/L3 读取；L1 使用 `SKILL.md` 中的快速验证契约。根据实际风险选择检查，记录准确命令、环境、结果和未执行项。

## 分级验证

| 等级 | 最低验证 | 默认不要求 |
|---|---|---|
| L1 | 修改前搜索、修改后旧值检查、diff、最多一个现成快速检查 | 新增测试、全量回归、完整启动 |
| L2 | 目标行为测试、目标模块回归、必要的直接消费者或契约检查 | 无证据支持的全仓测试 |
| L3 | 与风险匹配的安全、数据、契约、集成、运行、发布及回滚验证 | 仅依赖 Mock 或单元测试 |

## 需求追踪矩阵

仅在任务包含多项独立需求、跨多个模块、属于 L3，或持续时间较长而存在遗漏风险时维护。L1 不建立矩阵。

| 需求或风险 | 组件 | 状态 | 验证方式 | 证据或阻塞 |
|---|---|---|---|---|
| 具体行为 | 文件、模块或拟建单元 | 未开始/部分/完成/受阻 | 测试或运行检查 | 命令、输出或负责人 |

## 验证层级

- **静态和构建：** 格式、Lint、类型、依赖、Schema、迁移和配置校验。
- **单元和组件：** 核心行为、边界值、状态、幂等、错误、重试和权限决策。
- **契约：** API、事件、Tool、RPC、Schema、兼容性和消费者约定。
- **集成：** 数据库、跨边界依赖、并发、部分失败、恢复和可观测性。
- **运行与端到端：** 干净启动、健康状态、核心流程、失败流程和持久化行为。
- **发布与运维：** 迁移、灰度、监控、告警、回滚、容量和支持责任。

只选择当前等级和证据要求的层级，不把检查清单当成全部必做项。

## 证据等级

| 证据 | 能证明什么 |
|---|---|
| Mock 或 Fake | 本地分支逻辑 |
| 进程内 HTTP | 路由和序列化行为 |
| 严格契约 Stub | 与约定 Schema 兼容，不能证明提供方可用 |
| 共享测试环境 | 该环境中的跨服务行为 |
| 类生产或生产证据 | 已说明条件下的实际运维行为 |

不得静默用较低等级证据替代较高等级证据。

## 完成状态

| 声明 | 最低证据 |
|---|---|
| 已修改 | diff 已确认且目标值已处理 |
| 已实现 | 代码和针对性行为测试存在 |
| 自动化验证通过 | 已运行相关自动化测试 |
| 集成验证通过 | 已跨边界调用真实或严格契约依赖 |
| 可发布 | 运行、安全、迁移、运维和回滚门槛均通过 |

## 分级交付报告

- **L1：** 修改；旧值与 diff 检查；仅在需要时写注意项。
- **L2：** 行为变化；主要文件；测试结果；兼容性和剩余风险。
- **L3：** 范围、修改、验证、运行状态、兼容与发布、剩余风险和负责人。

未满足外部门槛时使用“受阻”，不要虚构成功或写成“有条件通过”。
