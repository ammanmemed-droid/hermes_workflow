# 后端项目开发与交付

## 核心原则

先判断任务等级，再采用与影响范围匹配的最小流程。局部、机械、可逆的修改默认快速处理；业务行为变化采用标准流程；安全、数据、公开契约或生产变更只在用户已明确授权或确认升级后采用高风险流程。

不得为了形式完整而扩大读取、设计、修改或验证范围。

## 与其他 Skill 协作

本 Skill 是后端项目任务的风险与范围路由器；专项 Skill 提供领域知识或工程方法。先遵守平台强制规则、用户指令和当前作用域内的仓库指令，再由本 Skill 分级，最后选择确有必要的专项 Skill。不得因为安装了某个 Skill 就自动扩大任务等级。

| 当前任务 | 默认组合 |
|---|---|
| L1 局部机械修改 | 仅执行本 Skill 的快速通道；不得仅因发生文件修改而调用 OpenSpec、需求设计、完整计划或 TDD |
| L2 Bug 或异常行为 | 本 Skill 控制范围；按需使用系统化调试和针对性 TDD |
| L2 新功能或业务行为变化 | 本 Skill 控制范围；按需使用需求澄清、设计和针对性 TDD |
| L3 契约、迁移或生产高风险变更 | 先通过升级确认门；确认后按需使用 OpenSpec 管理正式规格与变更，使用工程 Skill 实施和验证 |
| 明确的专项领域任务 | 可同时使用 Codex 内置或其他领域 Skill 获取直接相关知识和工具，但不得据此扩大修改与验证范围 |

OpenSpec 只在用户要求正式规格、变更提案或需求治理，或者已确认的契约、迁移、跨团队变更需要可追踪规格时使用。Superpowers 等流程 Skill 只在分级后的任务确实匹配其工程目的时使用。若上层强制规则与本 Skill 的 L1 上限冲突，遵守上层规则并立即说明冲突，不静默执行重流程。

需要在不同会话中稳定自动路由时，将 [AGENTS 路由模板](assets/AGENTS.backend-routing.md) 合并到全局或项目 `AGENTS.md`；合并前保留其中已有规则，不直接覆盖文件。

## 任务分级

| 等级 | 判断信号 | 默认方式 |
|---|---|---|
| L1 快速修改 | 目标明确、局部、机械、可逆，不改变业务、数据或权限语义 | 精准搜索、最小修改、有限验证 |
| L2 标准开发 | 业务行为、普通 Bug、接口能力或跨模块逻辑发生变化 | 局部分析、简短计划、针对性 TDD 和影响范围验证 |
| L3 高风险修改 | 权限、支付、数据迁移、公开契约、生产服务发现或不可逆操作 | 获得授权后执行完整影响、兼容、安全、迁移和发布检查 |

先选择等级；仅在 L2/L3 时按需阅读 [项目路径](references/delivery-paths.md)。项目路径决定工程方法，不决定流程深度。

## L1 快速通道

prefix、配置值、内部名称、日志文案和类似机械调整优先作为 L1 候选。Nacos 名称只有在未发现生产服务发现、多个消费者或兼容影响时才保持 L1。

固定执行：

1. 读取当前作用域内的仓库指令并检查目标文件是否有用户改动。
2. 使用用户给出的旧值、路径、配置键或标识符进行一次精准搜索；排除依赖、构建、缓存、日志和临时目录。
3. 只读取命中的权威定义、直接引用及必要相邻文件；不生成完整目录树。
4. 检查是否出现升级信号。出现时立即停止并使用“升级确认门”。
5. 没有升级信号时执行一次最小修改；不改生成物，不格式化整个文件，不更新依赖或锁文件。
6. 再次搜索旧值并检查 diff。历史记录或明确兼容别名可以保留并说明，不为清零而机械替换。
7. 最多运行一个仓库已有、快速且直接覆盖修改点的检查。
8. 满足停止条件后立即结束。

### L1 执行上限

- 不读取全部产品、架构、部署或运行资料。
- 不创建设计、完整计划或需求追踪矩阵。
- 不新增测试，不跑全量或多层回归，不启动完整应用、容器或共享环境。
- 不进行无关重构、清理、自动修复或格式化。
- 不因为推测风险而自行扩大搜索、修改或验证。

精准搜索无结果时，只允许一次基于大小写、命名形式或配置表达式的有依据变体搜索；仍无结果则报告并停止。

### L1 停止条件

- 目标值已完成最小修改；
- 范围内旧值已处理，或保留原因已说明；
- diff 只包含目标修改且未覆盖用户工作；
- 快速检查已通过，或没有适用检查；
- 没有未经确认的升级信号。

满足后不得为了获得更高置信度继续追加检查。

### L1 交付格式

- **修改：** 文件和具体值。
- **检查：** 旧值搜索、diff，以及实际运行的快速检查。
- **注意：** 仅在存在保留旧值、未验证项或风险时填写。

## 升级确认门

以下信号要求先确认：公开 API、事件、RPC、Schema 或外部配置契约；多个消费者或仓库外上下游；生产 Nacos 注册、订阅、Group、Namespace 或服务发现；兼容或灰度切换；权限、安全、支付、敏感数据；数据库迁移、回填或删除；生产部署、流量、基础设施；实际范围明显扩大。仅跨少量内部文件或模块不自动升级。

发现信号时停止扩大检查和修改，将同一轮发现合并为一次请求：

```text
发现：<具体证据>
可能影响：<一句话说明>
建议：升级为 L2/L3，并增加 <具体检查或修改>
是否确认升级？确认前不会扩大检查或修改。
```

建议等级必须与证据匹配：仅多个内部消费者通常建议 L2；生产服务发现、安全、支付、数据迁移、公开契约破坏性变更或不可逆操作建议 L3。

只有用户确认后才能升级。相同风险不重复询问；出现新的更高风险或范围实质变化时再确认。用户拒绝升级时，停止高影响部分并简短报告未处理项。

## L2 标准开发

明确当前行为、目标行为和验收标准，读取目标模块、直接上下游、相关测试与契约。使用简短计划，对业务行为或 Bug 采用针对性 TDD，实施最小完整修改；验证顺序为目标行为、目标模块、直接消费者，只有证据表明影响更广时才扩大回归。

当用户要求全项目审计、系统优化或扫除 Bug 时，先读取 [项目审计与优化](references/project-audit-and-optimization.md)，完成只读审计和基线，再按主题分批提交方案；获得用户确认后只实施当前批次。

读取 [验证与交付](references/verification-and-handoff.md)。发现 L3 信号时使用升级确认门。

## L3 高风险修改

只有用户已经明确知道具体高风险信号并明确授权相应范围，或发现信号后确认升级，才进入 L3。仅要求“修改生产配置”不代表用户已确认尚未说明的消费者、兼容、迁移或发布风险。区分只读分析、实施修改、部署和不可逆生产操作的授权，不将前一阶段授权自动扩展到后一阶段。

按需读取：

- 权限、安全或数据修改：[安全与数据变更](references/security-and-data-changes.md)
- 生产注册、消费者或服务发现：[服务发现变更](references/service-discovery-changes.md)
- 大模型、RAG、Agent、Embedding 或 Tool 的行为、权限、数据或副作用：[AI 系统检查](references/ai-system-checks.md)
- 验证和交付：[验证与交付](references/verification-and-handoff.md)

## 不可违反的规则

- 不覆盖、回退、删除或提交用户无关改动；目标位置与用户修改重叠时先询问。
- 未经明确授权，不扩大任务等级、修改范围、部署范围或外部副作用。
- 不静默改变公开契约、权限或持久化数据语义。
- 不把 Mock、单元测试或本地 HTTP 成功等同于真实集成或可发布。
- 不把模拟、占位、降级、未执行或未接真实依赖的结果描述为真实成功。
- 不把公司专属代码、内部地址、凭据、文档或事故细节带入个人通用 Skill。
- 没有当前需求、实测风险或已证明瓶颈时，不引入生产复杂度。
