# AI 系统交付检查

仅在修改影响大模型、Agent、RAG、Embedding 或 Tool 的行为、权限、数据使用、评测结果或外部副作用，并且用户已授权相应 L2/L3 范围时读取。单纯名称或无行为影响的配置调整不加载本文件。根据公司的威胁模型和评测制度调整具体要求。

## 数据和权限

- 在检索前强制执行租户、用户、文档和连接器权限，在返回数据或执行操作前再次校验。
- 在索引、缓存、RAG、导出和生成摘要中保持源系统访问控制。
- 减少 Prompt、日志、链路追踪、记忆、反馈和评测数据中的敏感内容。
- 明确保留、删除、数据驻留、加密和审计要求。
- 使用真实身份模型测试跨租户访问和权限撤销场景。

## Prompt、检索和 Tool 安全

- 将检索文档、邮件、网页内容和 Tool 输出视为不可信输入。
- 测试 Prompt Injection、指令冲突、污染检索、恶意附件和危险链接。
- 给予 Tool 最小权限并使用明确 Schema；校验参数、权限、副作用、超时、重试和幂等。
- 对不可逆、外部、财务、破坏性或高影响操作要求用户确认，除非制度明确允许自动执行。
- 不直接接受模型生成的标识符、引用、权限或业务事实，必须执行验证。

## 质量评测

- 修改 Prompt、模型、检索或编排前，先定义针对任务的评测数据集和成功标准。
- 根据场景评估事实性、可溯源性、引用准确性、指令遵循、拒绝行为、任务完成度和敏感信息泄漏。
- 覆盖正常、模糊、对抗、多语言、长上下文、空结果、过期数据和依赖失败场景。
- 使用相同数据集和配置比较候选方案，记录模型、Prompt、索引、参数、代码版本和评测日期。
- 对主观或高风险质量结论保留人工审查。

## 可靠性和运维

- 分别定义模型、检索、Tool、消息队列和流式输出的延迟预算与超时行为。
- 监控模型和 Tool 错误率、Token 与金额成本、缓存、队列积压、重试和用户中途放弃。
- 降级行为必须保持安全并让用户理解；缺少必要依据时，不静默返回看似合理的虚构内容。
- 验证流式结束、重复事件、取消、部分结果、重放和恢复行为。
- 将提供商可用性、配额、模型变更和索引新鲜度作为需要告警及运行手册的运维依赖。

## 发布门槛

所需的权限、隐私、安全、质量、可靠性、可观测性和回滚检查未执行前，不得宣称 AI 功能可发布。围绕 Mock 模型响应的单元测试只能证明代码行为，不能证明模型质量、检索权限或真实提供商集成。
