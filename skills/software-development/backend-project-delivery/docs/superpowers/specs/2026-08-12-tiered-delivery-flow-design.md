# 后端项目分级交付流程设计

## 目标

让局部机械修改快速完成，同时避免高风险修改在未获用户确认时扩大检查或实施范围。

## 任务分级

- **L1 快速修改：** prefix、配置值、内部名称、日志文案，以及未发现生产影响的 Nacos 名称调整。
- **L2 标准开发：** 业务行为变化、普通 Bug、接口能力或跨模块逻辑修改。
- **L3 高风险修改：** 权限、支付、数据库迁移、公开契约、生产服务发现或其他不可逆操作。

任务等级决定流程深度；Greenfield、Brownfield、Optimization、Stabilization 和 Rewrite 只决定工程方法。

## L1 快速通道

L1 固定采用以下有界流程：

1. 读取作用域内的仓库指令。
2. 使用用户提供的旧值、路径、配置键或标识符精准搜索。
3. 只读取定义位置和直接引用。
4. 检查是否出现升级信号。
5. 执行最小修改。
6. 再次搜索旧值并检查 diff。
7. 仅运行现成、快速且直接相关的检查。
8. 用几行内容报告修改和检查结果。

L1 不生成完整目录树，不读取全部架构资料，不创建设计或完整计划，不建立需求矩阵，不新增测试，不跑全量回归，不启动完整环境，也不进行无关重构或格式化。

完成目标修改、处理范围内旧值、确认 diff 聚焦且没有未确认升级信号后，立即结束。

## 最小上下文检索

默认不遍历完整项目。先精准搜索任务标识，再读取命中定义、直接引用及必要相邻文件。精准搜索无结果时，只允许一次基于大小写、命名形式或配置表达式的有依据变体搜索；仍无法定位则向用户报告，不自行扩大为全仓分析。

## 升级确认门

以下信号触发升级建议：公开契约、多个消费者、生产 Nacos 或服务发现、兼容切换、权限或安全、支付、数据迁移、生产部署或实际范围明显扩大。

发现信号时立即停止扩大搜索和修改，一次性向用户报告：

```text
发现：<具体证据>
可能影响：<一句话说明>
建议：升级为 L2/L3，并增加 <具体检查或修改>
是否确认升级？确认前不会扩大检查或修改。
```

只有用户确认后才能升级。相同风险不重复询问；出现新的更高风险或实质范围变化时再确认。

## L2 与 L3

L2 使用局部分析、简短计划、针对性 TDD 和受影响范围验证，不默认执行全仓回归。

L3 在用户原始请求已明确授权，或用户确认升级后，才执行完整影响分析、兼容、安全、迁移、灰度、回滚和发布验证。分析、修改、部署和不可逆生产操作分别授权。

## 验收标准

- 单点 prefix 或配置名修改进入 L1。
- L1 只做精准搜索、最小修改、旧值检查、diff 和可用的快速检查。
- L1 不默认新增测试、跑全量回归或生成完整目录树。
- 发现契约、消费者或生产影响时，AI 停止并一次性请求确认。
- 未经确认不扩大检查或修改。
- L2/L3 的验证范围与实际影响匹配。
- 最终报告长度与任务等级匹配。
