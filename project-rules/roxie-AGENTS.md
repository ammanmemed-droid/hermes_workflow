# 项目协作与工作流规范

## Skill 使用

- 根据用户需求和任务类型，自动选择当前可用的 Skill。
- Superpowers 按其适用场景正常使用，包括需求梳理、方案设计、计划、系统化调试、TDD、代码审查和完成前验证。
- OpenSpec 在需要正式规格、公开契约、跨团队协作、迁移方案或可追踪变更时使用。
- 文档、表格、PDF、图片等任务使用对应的专项 Skill。
- 不调用与当前任务无关的 Skill，不为了形式完整而扩大流程。
- Skill 当前不可用时应明确说明，并使用合理的替代方式继续处理。

## 开发流程

1. 理解需求并检查相关代码。
2. 根据任务复杂度选择必要的分析、设计和验证方式。
3. 涉及代码或业务行为修改时，先输出方案并等待用户审核确认。
4. 用户确认后再实施修改。
5. 开发完成后进行代码审查和必要测试。
6. 如审查发现阻断问题，先输出修复方案，等待用户确认后再修复。

## 执行纪律

- 不覆盖、删除或回退用户已有的无关改动。
- 不擅自扩大修改范围。
- 开发中出现超出原方案的修改或实质技术取舍时，暂停并询问用户。
- 不把单元测试或 Mock 成功描述为真实环境联调成功。
- Git 提交、推送、合并等操作必须由用户明确要求，禁止自动执行。
